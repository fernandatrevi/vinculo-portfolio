# Vínculo | Interview Preparation

## 45-second project pitch

Vínculo is a full-stack prototype I developed to explore how nonprofit organizations and donors could be connected through a platform that also supports administrative workflows. It brings together a React and TypeScript interface, a FastAPI backend and a PostgreSQL database. The project includes user accounts, organization memberships, permission controls and manual donor and donation records. I also designed a public directory and sample dashboard to communicate the product concept. It currently operates with fictional data and **does not process payments**. I present it as a software engineering and process-modeling project rather than a production-ready financial platform.

## Questions recruiters may ask

**What problem does Vínculo address?**

It explores how nonprofit project information, donor records and follow-up workflows could be organized together with differentiated access permissions. A measurable real-world impact has not yet been demonstrated.

**Which features are currently functional?**

According to the private project's documentation, the prototype includes a fictional directory, API-supported account registration and login, and persistent administrative records. Parts of the sample dashboard are local-only demonstrations.

**Where is information stored?**

PostgreSQL stores accounts, memberships and records managed by the API. Selected demonstration forms use browser-local storage.

**Can people make actual donations?**

No. The donation functionality currently records manual entries; there is no payment processor integration.

**What would you improve?**

I would prioritize security, privacy, automated end-to-end testing, deployed permission checks, email verification, reconciliation workflows and reliable reporting metrics.

**How is this relevant to a data analytics position?**

The project involves defining structured entities, maintaining record consistency and designing possible indicators for fundraising and donor follow-up. It does not by itself demonstrate experience with Snowflake, Power BI or Revenue Management.

**Why is the source code private?**

The public repository explains the design decisions, technical architecture and limitations and provides a demonstration link without exposing the application's private Git repository.

## Note for technical interviews

Be prepared to distinguish functionality implemented in the API from the separate sample dashboard. Do not claim to process real payments, to have confirmed business impact or to have completed a security certification.
